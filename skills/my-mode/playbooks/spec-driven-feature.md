### Spec-driven feature

**設計の所有者はあなた。計画し、レビューし、検証する。** 実装は委譲する。主導権は手放さない。

poteto-mode の Feature プレイブックに、仕様の読み書きを前後に足したもの。Feature の手順 1 から 8 はそのまま使う。

1. `docs/specs/<slug>.md` を探す。あれば読む。なければ **spec-first** スキルで書く。仕様の完了条件を、ここから先の ToDo の先頭に逐語でコピーする。
2. 仕様の完了条件のうち、実験で決まるものを Prototype で先に決める。仕様を更新する。
3. **検証方法** に書いたスクリプトまたはテストを、機能より先に作る。この時点では失敗するのが正しい（principle-sequence-verifiable-units、tdd）。
4. poteto-mode の Feature プレイブック手順 1 から 7 を実行する（`how`、`architect`、スループットチェックポイント、委譲、同じ面での検証、小さなコミット、必要なら `interrogate`）。委譲のプロンプトには仕様ファイルのパスと、担当する完了条件の番号を渡す。
5. 完了条件を 1 つずつ、手順 3 のスクリプトで確かめる。全部が通らなければ完了ではない。通らない項目は `未達: <理由>` を付けて返答に残す。
6. 実装中に仕様が変わったなら、仕様ファイルを直し、同じ PR に含める。
7. **Opening a PR** を実行する。PR 本文の先頭に仕様へのリンクを置く。

**返答:** 仕様へのパス。完了条件ごとの結果（通った / 未達 / 仕様から削除、とその根拠）。仕様の変更点。失敗から成功に変わった検証出力をそのまま貼る。
